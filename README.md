# 数字展品使用授权核验系统

供小型展馆核对数字展品使用授权的 Web 应用：策展人登记数字素材与素材之间的**来源关系**，
录入每份授权的**媒介、地区、有效期与撤销状态**；选取素材组成展览包并给出**展示媒介、地区、
展期起止日期**后，系统沿**全部来源链**逐节点核验授权覆盖情况，不合格节点与来源路径逐一列出。
核验通过方可发布；发布以数据库事务**原子保存不可变的核验快照与素材清单**。授权随后变更时
自动重算资格，仅把不再合格的已发布包标记为**需复核**（原快照保留）；同时编辑导致核验依据
过期时拒绝发布并提示重试。

技术栈：Node.js（Express）+ SQLite（better-sqlite3，WAL 模式）+ 原生浏览器前端（无需构建）。

---

## 一、一键启动（Docker Compose，推荐）

前置条件：已安装 Docker 与 Docker Compose。

```bash
docker compose up --build
```

启动后浏览器访问：

- **http://localhost:3000**

首次启动自动建表，并在空库时写入一套演示数据（见文末）。停止：

```bash
docker compose down            # 保留数据（命名卷 app-data）
docker compose down -v         # 同时删除数据库卷
```

## 二、本机直接运行（Node.js 20+）

```bash
npm install
npm run init-db       # 初始化数据库（建表，幂等）。服务启动时也会自动执行
npm run seed          # 可选：写入演示数据（仅空库时生效；启动时默认自动写入）
npm start
```

访问 **http://localhost:3000**。数据库文件默认位于 `data/app.db`。

## 三、配置项（环境变量）

| 变量 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `3000` | HTTP 监听端口 |

`ports: - "8080:3000"` 后访问 http://localhost:8080。

## 四、使用流程

1. **素材与来源**：登记素材；建立“上游素材 → 被下游素材使用”的来源关系。
   任何会导致来源链**成环**的关系都会被拒绝并提示环上的节点。
2. **授权登记**：为素材录入授权方、媒介、地区、起止日期、撤销状态与文件编号。
   媒介/地区为精确匹配，`*` 表示全媒介 / 全球。
3. **展览包**：新建草稿 → 勾选素材 → 填写展示媒介、地区与起止日期 → **核验资格**。
   - 系统对每个入选项向上游枚举**全部来源路径**，对所有可达节点逐一判定：
     至少存在一份**未撤销**、媒介与地区匹配、且授权有效期**完整覆盖整段展期**的授权。
   - 不合格节点给出原因（缺少授权 / 均已撤销 / 不覆盖媒介地区或整段展期）及
     从入选项到该节点的全部来源路径。
   - 日期非法、未选素材或来源关系成环时无法核验、**不得发布**。
4. **发布**：单个 SQLite 事务内完成：复核核验依据版本 → 重算资格 → 写入
   `verification_snapshot`（完整核验结果、节点判定、来源路径、素材清单 JSON，之后永不修改）
   → 置包为已发布。
5. **授权变更后的重算**：新增/修改/删除/撤销授权、变更来源关系或素材后，系统在同一事务内
   重算所有**已发布**包（自动只做降级）：
   - 仍然合格：状态不变，原快照继续有效；
   - 不再合格：标记为**需复核**，原快照完整保留；
   - 资格恢复后系统**不会**自动改回已发布——须策展人打开包重新核验、确认合格后再次发布
     （生成新快照，旧快照仍在）。
   草稿/待发布包不缓存结论，每次打开或点“核验”都按当前数据重新核验。
6. **并发编辑保护（核验依据版本）**：素材/来源/授权的每次变更都会使 `basis_version` +1。
   前端先核验、后发布；若两次之间有他人编辑，发布返回 409“核验依据已过期”，
   前端自动重新核验并提示重试。

## 五、HTTP API 摘要

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/basis` | 当前核验依据版本 |
| GET/POST | `/api/materials` | 素材列表 / 新建 |
| PUT/DELETE | `/api/materials/:id` | 改 / 删（有关联关系、授权或被包使用时拒绝删除） |
| GET/POST | `/api/edges` | 来源关系列表 / 新建（服务端成环检测） |
| DELETE | `/api/edges/:id` | 删除来源关系（触发已发布包重算） |
| GET/POST | `/api/authorizations` | 授权列表 / 新建 |
| PUT/DELETE | `/api/authorizations/:id` | 修改 / 删除 |
| POST | `/api/authorizations/:id/revoke` | 撤销授权（触发重算） |
| GET/POST | `/api/packages` | 包列表 / 新建草稿 |
| GET/DELETE | `/api/packages/:id` | 详情 / 删除（仅草稿可删） |
| PUT | `/api/packages/:id` | 保存名称与使用范围（媒介/地区/起止日期；仅草稿） |
| PUT | `/api/packages/:id/items` | 保存素材清单（仅草稿） |
| POST | `/api/packages/:id/verify` | 试核验，返回节点判定、失败原因与来源路径 |
| POST | `/api/packages/:id/publish` | 发布（body 带 `basisVersion`；过期返回 409） |
| GET | `/api/packages/:id/snapshots` | 包的快照列表 |
| GET | `/api/snapshots/:id` | 快照完整内容（不可变 JSON） |
| POST | `/api/recompute` | 手动触发已发布包重算 |

## 六、数据模型要点

- `material`：素材。
- `source_edge(source_id → target_id)`：`source` 被 `target` 使用；有唯一约束且禁止自环，
  应用层在写入前做 DAG 成环检测。
- `authorization`：授权（媒介/地区/有效期/撤销），数据库约束 `start_date ≤ end_date`。
- `exhibition_package`：`draft` / `published` / `needs_review` 三态。
- `package_material`：包素材清单；发布后不可改（仅草稿可写）。
- `verification_snapshot`：发布快照，只追加、不修改不删除（应用层无更新入口）。
- `meta.basis_version`：由 SQLite 触发器在素材/关系/授权增删改时自动 +1。

## 七、演示数据

系统自带：5 件素材（互动展项引用油画扫描件、历史照片与配乐；导览片引用历史照片）、
6 份授权（含 1 份已撤销、1 份在 2026-06-30 到期的配乐授权）、草稿包
《城与人》常设展（草稿）（展厅大屏 / 中国大陆 / 2026-01-01 ~ 2026-12-31）。

体验路径：打开草稿 → 核验（配乐节点不合格并显示来源路径）；
在“授权登记”里把配乐授权延长到 2026 年底后重新核验即可发布；
发布后再撤销或缩短任一上游授权，返回列表可见该包自动变为“需复核”，快照仍可查看。
